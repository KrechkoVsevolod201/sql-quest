# SQL Quest Content Author

Используй этот навык при добавлении учебных баз, упражнений и примеров для SQL Quest.

## Формат учебного контента

- Учебные базы и наборы задач находятся в `sqlgame/core.py`: `DATABASES`, `MODULES`, `EXERCISES`.
- Упражнение содержит уникальный `id`, `module`, `database`, короткий `title`, `difficulty` (1–3), понятный `prompt`, обучающий `hint`, исполняемый `solution` и краткое `explanation`.
- Не включай `solution` и `explanation` в публичный API списка заданий; `list_exercises` намеренно скрывает их.
- Seed-данные должны быть компактными, детерминированными и покрывать граничные случаи: пустые группы, повторяющиеся значения, NULL (если уместно), несколько связанных строк.
- Имена и значения в SQLite должны поддерживать текст заданий; для русских строк используй UTF-8.

## Проверка каждого задания

1. Инициализируй базу в тестовой директории и проверь `grade(id, solution)`.
2. Убедись, что запрос ученика можно выразить через нужную тему модуля и не требует возможностей за пределами SQLite.
3. Проверь, что результат имеет осмысленную форму, а несколько альтернативных запросов могут вернуть тот же правильный результат.
4. Не рассчитывай на порядок строк: базовый grader сравнивает результаты как мультимножество. Если сортировка — учебная цель, явно укажи её в prompt и при необходимости добавь отдельный UX-критерий.
5. Запусти `py -3 -m unittest discover -s tests -v` после изменения ядра.

## Генерация с AI

MCP tool `generate_exercise` возвращает JSON с `title`, `description`, `schema_sql`, `seed_sql`, `task`, `hint`, `solution_sql`, `explanation`. Рассматривай ответ модели как черновик: проверь SQL на временной SQLite-базе до добавления в встроенный каталог. Не вставляй секреты, персональные данные и команды, обращающиеся к файловой системе.

## Сопровождение

Сохраняй изоляцию: уроки запускаются на read-only учебных файлах, пользовательские DDL/DML — только в отдельной лабораторной базе. При добавлении API-маршрута документируй его в `README.md`.
